## Verdict

- **I1: PASS for Vault outputs created by this code (v7); FAIL for pre-existing v6 outputs until they are re-locked.** A clean-database test builds a wallet from the mnemonic alone, with no SQLite rows, no SecureStore Vault meta and no backup, recovers every v7 output from public chain data, and withdraws with any one committed key and its PIN. This covers N = 2..5 and every key position, after deposits, a re-lock and a remainder. Each input passes the strict interpreter and an independent noble P-256 check. The proof used a software MockYubiKey (real P-256) and an in-memory chain. It has not been run against a real indexer, a node, or a physical key (NEW-04, NEW-05). Outputs deposited before this change carry no on-chain marker or descriptor. They still need the old database or the encrypted backup (INT-01, INT-06, XQ-012 residual).
- **I2: PASS for v7; FAIL for pre-existing v6 outputs.** v7 stores no salt anywhere: not in the database, the export, backup chunks or the descriptor plaintext at rest. The salt comes only from the wallet root. Stolen database + committed key + PIN, mnemonic only, wrong PIN, an unenrolled key, database + SecureStore with no key, and an external BRC-100 caller all fail closed; each has a positive control (`proofBar.exclusionMatrix`, 14 tests). A v6 output's customInstructions still hold its salt in plaintext, so stolen database + key + PIN can spend it; a named residual test pins this (INT-10, partial). Forged Vault meta or enrollment drafts are refused by root-keyed integrity tags (XR-001, XR-002). Restoring an older, validly tagged SecureStore snapshot is the remaining gap (NEW-02); it cannot yield a spend without the mnemonic.
- **I3: PASS.** A real `@bsv/wallet-toolbox-mobile` wallet on real SQLite never selects a Vault UTXO from localpay, the handle/MessageBox rail, the address rail, Mandala coin selection or the offline pending queue. Each case has a positive control. The external guard and the storage backstop each deny discovery and mutation, including with the other bypassed (`proofBar.railIsolation`, 14 tests). The new reserved protocols (`vault marker`, `vault descriptor`, `vault meta`, `connection authority`, and the internal payment-rail namespaces from XR-020) are denied to paired callers.
- **Open Critical/High:** INT-10 (Critical, v6 salts at rest until re-lock). High, blocked on a protocol, product or format decision: XR-011, XR-014, XR-028, XR-053, XR-068, XR-089, XR-095, XR-099, XR-110. High, needs hardware or network: INT-05, NEW-04, NEW-05. The not-fixed table below gives each blocker and what would close it.
- **Ship Vault creation? No.** The v7 deposit shape (~45 KB R1C lock + 1-sat marker + OP_RETURN descriptor) has not been broadcast to ARC or mined. No exact-byte v7 spend has been accepted by a node. The WhatsOnChain response shapes `wocChainLookup` depends on are unverified. No v7 flow has run on a physical YubiKey (NEW-04, NEW-05, INT-05, XQ-003). Those are spend-validity and lockout claims at High, so creation stays off. Commit `e39322d9` removes `EXPO_PUBLIC_VAULT_ENABLED` from the production EAS profile, and `__tests__/vaultShipGate.test.ts` pins that. Development and dev-physical keep it on for gathering the proofs. Existing vaults stay reachable for a full withdrawal (INT-08). This reverses the 2026-09-12 decision to ship the flag in production for TestFlight; reverting `e39322d9` restores it.

## Residual risk

- **Compromised phone + present, unlocked token.** A YubiKey has no display. A compromised app or OS can have a present token sign an attacker-chosen digest once the PIN is entered, and the touch policy is `cached`. Hardware non-exportability does not make the phone a trusted display. Out of reach for any software fix here.
- **Legacy v6 outputs.** Until re-locked they still need the database or backup to recover, and still carry a plaintext salt (INT-01/06/10, XQ-012). A re-lock converts them, but it creates an output, so it is refused while creation is off in production. The owner needs to decide how v6 holders migrate once the ship gate lifts. There is no in-app nudge yet.
- **Miner/ARC policy and the indexer — unproven.** Nothing was broadcast. The ~45 KB lock, ~2.5 KB witness, 1-sat marker and ~1.5 KB OP_RETURN descriptor might be refused by TAAL/GorillaPool ARC or miners, and the WhatsOnChain `/address/{a}/history`, `/tx/{txid}/beef`, `/tx/hash/{txid}` and `/tx/{txid}/out/{vout}` shapes are assumptions. `wocChainLookup` fails closed on unknown shapes (reports a problem rather than a miss or a false "unspent"). A dishonest indexer can hide markers, which blocks recovery but cannot forge it: descriptors are authenticated by the root-derived key and every lock is rebuilt byte-exactly.
- **YubiKey firmware and native code — not run on hardware.** Behaviour in firmware 5.7.4+ was inferred from status words and certificate extensions (known breakage history). The iOS `activeConnection` reuse (XQ-003) has a recorded code delta but is unshipped. The Android Kotlin receive-size ceilings (XR-090) and Android keystore rotation (XQ-013) are unbuilt or unrun, and the native signing-equivalence check (XQ-001) is not done. No NFC/USB, attestation, PIN/PUK or physical enroll-to-withdraw run was done in this pass (INT-05, NEW-05).
- **Protocol-level gaps with other parties.** These are recorded as design deltas, not half-fixes: LocalPay ack binding to the exact frame (XR-089); proof of non-delivery for a QR payee who has not broadcast (XR-095, XR-103 residual); a recipient-signed PeerPay delivery receipt (XR-053); overlay admission amounts for multi-hop token conservation (XR-099); backup position/freshness binding and an appData-only chunk shape (XR-011, XR-014, XR-055); a chaintracks header-range API (XR-068); and an @bsv/mandala pre-hand-over journal (XR-034 residual).
- **Product decisions still open:** the auto-approve default and per-origin caps (XR-028); cross-network address warn vs block (XR-057); a paced share-printing flow (XR-110); how an encrypted export gets its key to the importing device (XR-086).
- **Platform limits:** no connect-time/redirect check against DNS rebinding (XR-073, XR-072, XR-024); `expo-image` prefetch has no deadline or byte cap (XR-075); React Native fetch cannot stream a body without Content-Length (XR-013).
- **Tests:** `trustIcon.test.ts` failed intermittently (5 cases, 2 of 4 full root runs) and never in isolation. Its swallowed error hides the cause, so a follow-up task is filed. Crash, fault-injection and device storage semantics were not executed (XQ-002, XQ-005).
