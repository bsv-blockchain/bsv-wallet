# Browser Bridge Android Loopback Kit, Milestone 1 (Project 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@bsv/expo-android-wallet-bridge` milestone 1 (foreground mode): a Kotlin loopback HTTP server, launch trampoline, foreground service and Expo module, the TypeScript protocol controller, the config plugin, a stand-in page client and demo, and the Bitcoin SV Wallet adoption, so a page in Android Chrome can use the wallet as its BRC-100 wallet through the P1 core. M2 (overlay) is a gated appendix.

**Architecture:** The pure BRC-185 §4.1 HTTP semantics (router, CORS, status table, launch proof MACs, Host check, endpoint list) live in the toolbox (`core/bridge/loopback/`) and are jest-tested. Kotlin is a dumb pipe: strict HTTP/1.1 parser, dual-family exclusive bind, hold-open responses, process-memory `LaunchStore`, Kotlin deadline timers, foreground service. A TS controller in the kit wires native events to the router and to P1 `dispatch()`, owns the session machine, the unsettled-binding gate and the token outbox. The host adopts the kit with one plugin entry and a short list of edits.

**Tech Stack:** TypeScript, React Native 0.86 / Expo SDK 57, Kotlin (ExpoModulesCore; the version comes from the Expo Gradle plugin, the pure-JVM test projects use KGP 2.2.10), JUnit 4.13.2 (pure JVM), `@noble/curves` + `@noble/hashes`, `expo-secure-store`, esbuild, jest, Pixel_9 AVD.

**Spec:** `docs/superpowers/specs/2026-10-28-browser-bridge-android-design.md` (revision 3; "spec 7.5" = its section 7.5). Core spec: `docs/superpowers/specs/2026-10-27-browser-bridge-core-design.md` ("P1 6.5"). Prior plan mirrored: `docs/superpowers/plans/2026-10-28-browser-bridge-ios-kit.md`. ## Review Focus

Inputs the spec implies but its test list does not name, plus the cross-task risks; each has a test in the named task.
1. A page sends `Origin: https://Example.com` (uppercase host) or `https://example.com:443`: must be `403`, empty body, no CORS headers, never normalised (Task 6 `uppercase host and explicit default port origins are refused 403 without CORS`).
2. `takeLaunches()` returns two records for one epoch, or the same URI again after a JS reload: exactly one record exists and the epoch stays tombstoned (Task 16 `duplicate epoch in one take yields one record`, `burnt epoch is not re-created by a later take`).
3. The host detaches and re-attaches while a connect is parked: the parked connect is answered `503` `CONFIGURATION_ERROR` `not-sent` at detach, its launch record stays burnt, and re-attach does not resurrect it (Task 16 `detach during a parked connect answers 503 and re-attach does not resume it`).
4. `ensureService()` returns false (Android refused the foreground service): no port opens, the session stays IDLE and the launch record is kept unburnt for one retry within its life (Task 16 `ensureService false leaves IDLE with no listener`).
5. A POST body whose UTF-8 byte length differs from its character count (multibyte JSON): Kotlin reads exactly `Content-Length` bytes and rejects a body shorter or longer than declared (Task 9 `multibyte body is read by byte length`, `short body then EOF is 400`).
6. Two cold connects both park, then are released in one synchronous turn: the gate re-check at `connectExplicit` gives the second `429` and exactly one binding exists (Task 7 `second parked connect gets 429 in the same turn as connectExplicit`, Task 17 `two parked connects released together yield one binding`).
7. The Kotlin pure-JVM include list stays pure: no file in it imports `android.*` or `androidx.*`, so Android posting code lives in `AttentionPoster.kt`, never in a listed file (Task 9 `check-pure.sh`, run before every `KT`).
8. The notification Disconnect action and the notification taps reach JS: Disconnect runs the native stop and emits `onServerStopped {reason:'user-disconnect'}` (Task 17 `user-disconnect closes every binding lost`, Task 24 e2e Disconnect case); generic text and private visibility are observed on the device (Task 24 notification case).

The review list held 25 items. Items 1 and 17 (both: `Attention.kt` must stay pure) and items 9 and 18 (both: the i18n keys must exist before the notices) are duplicates and were applied once. Everything else was applied. Where the suggested fix was changed, the change and the reason are:

- **Pure Kotlin include list.** Applied by splitting: the pure spec is `NotificationSpec.kt` (plain `Int` importance and visibility with a comment mapping them to the Android constants), posting is `AttentionPoster.kt` (Android only, not on the include list), and `check-pure.sh` fails any listed file that imports `android.*` or `androidx.*`. Added as Review Focus 7.
- **Order.** The i18n and test-id task moved up to Task 5 (right after the launch-proof task) instead of being re-ordered inside Tasks 14 and 15, because it is independent of the router and controller work and Task 22 and Task 24 need its test ids too. Task 14 split into Tasks 17 and 18, the router into Tasks 6 to 8, and the old Task 5 / Task 13 type mismatch is settled by defining every port type once in `routerTypes.ts` (Task 6) with Task 16 implementing them.
- **Binding ledger.** The `BindingLedgerPort` interface lives in the toolbox (Task 6) so the router can consume it; the implementation is `controller/bindingLedger.ts` in Task 16. The router's old `isGone` and `bindingSecrets` moved onto it.
- **Disconnect.** The first suggested mechanism was used (native stop with reason `user-disconnect` through the existing `onServerStopped` event), so no new event exists. Verified in Task 17 (unit) and Task 24 case 17 (device).
- **reset(ctx).** The `onReset` hook was chosen over dropping the claim. M1 has no UI caller of `reset(ctx)`; the hook is covered by tests in Tasks 15 and 17.
- **Write stall test.** The suggestion used a fake clock; a blocking socket write cannot be driven by one, so `writeStallMs` is injectable (300 ms in the test) against a peer that never reads.
- **Kotlin test fallback.** The suggested `kotlinc` plus junit console jar is not available (`kotlinc` is not installed and the Gradle cache holds only 9.3.1). The ladder is: KGP 2.2.10 on Gradle 9.3.1, then a downloaded Gradle 8.14.x, then `:testDebugUnitTest` in the host build, then compile-only with the unrun test classes listed as device gates.
- **60 s self-stop.** Checked through the ports-exhausted scenario (Task 22 step 4b), which starts the service with no server, rather than a separate artificial case.
- **Chrome upgrade and Maestro.** Both are downloads that need owner approval, so they are device gates, never attempted. `chromeAtLeast(142)` branches Tasks 22 and 24, and the uiautomator sequence is the default wallet-creation path.
- **HW uncommitted edits.** Task 1 records the diff of the two uncommitted files in `safari-bridge` and whether the baseline needs them; nothing is copied silently.
